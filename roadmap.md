# Roadmap проекта Support Desk

Ветка: `feature/frontend-auth-dashboard`

Roadmap отражает фактическое состояние кода на 23.11.2026. Задача считается завершённой только при наличии реализации; пункты, требующие внешней системы или ручной эксплуатационной проверки, отмечаются отдельно.

## Целевой процесс обработки обращений

1. Клиент создаёт обращение из личного кабинета.
2. Новое обращение автоматически попадает в очередь единственной активной основной роли, выбранной администратором как первый уровень.
3. Сотрудник этой роли атомарно забирает обращение; один запрос не может быть захвачен двумя сотрудниками.
4. Сотрудник передаёт обращение только по настроенному маршруту.
5. После передачи обращение снимается с текущего сотрудника и становится доступно в очереди целевой роли.
6. Сотрудники не создают обращения от имени клиентов.

### Этап 3. Маршрутизация

- [x] Сохранён интерфейс настройки входящих и исходящих маршрутов.
- [x] Передача проверяет право сотрудника, его членство в исходной роли и наличие явно настроенного маршрута.
- [x] При передаче очищается ответственный сотрудник, меняется очередь и время постановки в очередь, статус возвращается в очередь.
- [x] Системное событие передачи записывается вместе с изменением обращения.
- [x] Автоматическая передача использует маршрут по умолчанию и создаёт системное событие.
- [x] Вынесен отдельный Compose-сервис `worker`; настроены запуск после миграций, `restart: unless-stopped`, параметры интервала/пакета и журналы ошибок. Worker не запускается внутри Gunicorn.
- [x] Выборка автопередачи использует транзакционный `SELECT FOR UPDATE SKIP LOCKED`; изменение обращения и системное событие фиксируются одной транзакцией, ошибки приводят к rollback.
- [x] Добавлены PostgreSQL integration-тесты двух параллельных worker-процессов и rollback при ошибке перед commit; тесты используют отдельную БД из `SUPPORT_TEST_POSTGRES_URL`.
- [x] Worker корректно обрабатывает `SIGINT` / `SIGTERM`: завершает текущий цикл, восстанавливает обработчики сигналов и освобождает сессию БД; добавлен unit-тест штатного завершения по `SIGTERM`.

## Незавершённые элементы кода и продукта

### Приоритет 1 — исправить до реального использования

- [x] **Объектная безопасность JSON API** — `app/api/routes.py`: служебные endpoints доступны только активным сотрудникам; клиенты получают 403. API использует ту же модель области доступа, что и web-интерфейс: собственные обращения и незахваченные обращения статусов `OPEN` / `WAITING_EMPLOYEE` в активных основных ролях; специальные роли, чужие захваченные обращения и закрытые обращения очереди не дают доступ. Списки клиентов ограничены клиентами видимых обращений; список сотрудников ограничен коллегами по активным ролям. Администратор сохраняет полный доступ. Для недоступного обращения возвращается 404.
- [x] **Защита сообщений в JSON API** — скрыты soft-deleted сообщения; внутренние заметки выдаются и создаются только при наличии `dialogs.add_internal_note`; публичный ответ требует `dialogs.reply`. API не содержит endpoints загрузки/скачивания вложений.
- [x] **Валидация и ошибки JSON API** — требуется JSON-объект, проверяются типы и длины строк, формат email, логические значения и пароль сотрудника; дубликаты email возвращают 409. Ошибки API возвращаются в едином JSON-конверте.
- [x] **Документация JSON API** — добавлен `docs/api.md` с endpoints, разрешениями, правилами объектного доступа и текущими ограничениями.
- [x] **Проверка JSON API** — пользователь подтвердил успешный запуск полного набора тестов после исправления тестовых данных.
- [x] **Операционная автопередача — базовая реализация** — отдельный Compose worker, автоматический перезапуск, пакетная обработка, логи ошибок и конкурентная выборка с `SKIP LOCKED`. Остается проверка на реальном PostgreSQL и настройка внешних оповещений.
- [ ] **Регистрация из основной системы** — `app/services/registration_provider.py`, `docs/registration-integration.md`: HTTP-адаптер реализован, но реальная интеграция не завершена без endpoint и согласованного протокола со стороны основной системы. Текущий mock предназначен только для разработки.
- [ ] **Сброс пароля клиента** — `app/services/password_reset_service.py`, `app/web/client_password_reset.py`: токены и SMTP-отправка реализованы, но необходимо настроить SMTP и проверить доставку/повторные запросы в целевой среде.
- [ ] **Проверка регистрации** — `app/web/routes.py`: локальная запись аккаунта создаётся до погашения токена в основной системе. При сбое погашения показывается предупреждение, но требуется операционный сценарий повторной синхронизации/сверки таких аккаунтов.

### Приоритет 2 — явно незавершённые интерфейсы

- [x] **Рабочие процессы — маршрутизация** — добавлен общий редактор переходов между активными основными ролями, выбора маршрута по умолчанию и времени автопередачи. Используется существующий `RoleRoute` и единый сервис валидации; защищено разрешением `roles.manage_routing`. Полноценный конструктор произвольных триггеров и действий остаётся отдельной будущей задачей. Добавлены тесты создания, удаления, отказа для маршрута роли в саму себя и проверки прав (`tests/test_workflow_editor.py`).
- [x] **Каналы — Web** — добавлена настройка включения/приостановки приёма новых обращений через клиентский веб-кабинет. При отключении скрывается действие создания обращения и сервер перенаправляет прямой переход к форме; история остаётся доступной. Telegram, VK, виджет и внешние обработчики не реализованы.
- [ ] **Интеграции** — заглушка; нет UI управления внешними системами и жизненным циклом интеграционных ключей.
- [ ] **Корпоративная система** — заглушка; нет полноценной синхронизации клиентов/сотрудников, разрешения конфликтов и обновления связей по внешним идентификаторам.
- [x] **Модерация** — словарный фильтр и классификатор имеют независимые переключатели и порог уверенности. Справочник поддерживает категории, режимы `WHOLE_WORD` / `SUBSTRING` / `EXACT`, поиск, массовое добавление, включение/отключение, удаление и импорт/экспорт CSV/TXT с валидацией и дедупликацией. Журнал фиксирует решения `ACCEPTED` / `REJECTED` / `BYPASSED`, источник, совпавшую запись, категорию, уверенность и модель; доступны фильтры, постраничный просмотр и отдельный срок хранения (по умолчанию «Никогда»), автоматическая очистка worker и CLI.
- [x] **Обратная связь при модерации** — формы клиента отправляют сообщения через AJAX и показывают анимацию «Обработка сообщения…»; при успешной проверке отображается подтверждение отправки специалисту, при отклонении — причина и рекомендации модели по исправлению. Инструкции классификатору запрещают требовать недоступные клиенту сведения и предлагают альтернативные способы описания проблемы. Модерация полностью обходится после захвата обращения сотрудником первого уровня или передачи в другую роль.
- [ ] **Фоновая обработка Ollama** — перенести длительный синхронный вызов классификатора в worker, чтобы не удерживать HTTP-запрос до завершения проверки. Сейчас ожидание асинхронно только для интерфейса браузера.
- [ ] **AI** — реализованы настройки Ollama (URL, модель, системный промт и промт классификации), отдельный переключатель использования модели, API-клиент `/api/tags` и `/api/chat`, валидация структуры и диапазона JSON-классификации; Compose поднимает Ollama и загружает модель. Текст клиента передаётся отдельным пользовательским сообщением, а инструкции и примеры — системным, чтобы не смешивать доверенные инструкции с недоверенным содержимым. Нужны метрики качества и асинхронная интеграция для долгих запросов. Отдельный AI-помощник для сбора недостающих данных и ответов клиенту ещё не реализован.
- [ ] **Уведомления** — заглушка; нет каналов доставки, шаблонов, пользовательских настроек и очереди уведомлений.
- [x] **Карточки клиентов и сотрудников** — добавлены серверный поиск по основным полям, фильтр связанных/локальных аккаунтов клиентов, фильтры статуса и роли сотрудников, постраничная выборка по 25 записей и навигация с сохранением фильтров. Добавлены тесты `tests/test_directory_views.py`.
- [x] **Приглашения сотрудников** — добавлены одноразовые ссылки с 72-часовым сроком, хранение только SHA-256-хеша токена, назначение выбранной основной роли, установка пароля от 12 символов, отзыв и замена старых приглашений, защита от повторного принятия и гонки отзыва/активации. Письма отправляются через SMTP; при ошибке доставки приглашение автоматически отзывается. Добавлены тесты `tests/test_employee_invitations.py`.
